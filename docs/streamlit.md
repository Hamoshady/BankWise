# واجهة BankWise بـStreamlit

الواجهة المحلية: http://127.0.0.1:8501

```bash
/usr/bin/python3 scripts/local_api.py up
/usr/bin/python3 scripts/local_ui.py up
```

المشغّل يعيد بناء صورة الواجهة فقط لو الملفات اتغيرت، ويشغّل حاوية
`bankwise-ui-local` على loopback مع إعادة تشغيل `unless-stopped`.
الواجهة منفصلة عن الـAPI وعن مكتبات OCR وCUDA؛ لا تحتاج إعادة بناء نماذج الذكاء الاصطناعي.

## الدخول والاستخدام

- سجّل الدخول بـ`demo_alice` أو `demo_bob`. كلمات المرور موجودة في الملف الخاص
  `~/.config/bankwise_ai/demo-logins.json`، ولا تقرأها الواجهة أو تعرضها تلقائيًا.
- **نظرة عامة:** الرصيد، الحسابات، آخر 100 معاملة، وتنزيل كشف PDF.
- **المساعد الذكي:** محادثة عربية، عرض مصادر الإجابات، ونموذج لاستكمال الحقول الناقصة.
- **التحويلات:** اختار الحساب المصدر، والصق UUID حساب المستفيد من ملف الدخول أو صفحة حساباته.
  جهّز الطلب ثم راجع التفاصيل، اعرض OTP التجريبي، واكتب الكود مع تفعيل الموافقة.
- **القروض:** حاسبة قسط بفائدة يحددها المستخدم، وطلب تجريبي ينتقل للمراجعة بعد التأكيد.
- **إدارة الحسابات:** اختيار الحسابات وطلبات الفتح والإغلاق.
- **الهوية:** رفع صورتين للفحص المحلي، فقط للحسابات صاحبة دور `identity_processor`.
  حسابات Demo لا تملك الدور؛ الواجهة لا تمنح صلاحيات ولا تعتمد KYC تلقائيًا.
- **المعرفة والسياسات:** البحث في RAG؛ دور `knowledge_user` يمكنه إضافة مستندات خاصة.

## الجلسات والتأكيد

الواجهة تستدعي الـAPI الموجود؛ الـJWT والصلاحيات والـKYC والـOTP والرصيد تُفحص في السيرفر.
كلمة المرور لا تُحفظ بعد الدخول، والتوكن محفوظ في ذاكرة جلسة Streamlit فقط.
لا يوجد cache مشترك للأرصدة أو المحادثات أو الملفات. تسجيل الخروج يحاول إلغاء التوكن
ويمسح بيانات الجلسة. عند انتهاء الصلاحية يلزم الدخول من جديد.

تغيير tab أو إعادة عرض Streamlit لا ينفّذ العملية تلقائيًا. فشل الاتصال أثناء التأكيد
يُبقي معرّف العملية نفسه لإعادة تأكيدها بأمان، وليس إنشاء تحويل آخر.
طلب جديد لا يُجهز أثناء وجود عملية معلقة في الواجهة. التأكيد يحتاج موافقة checkbox
وستة أرقام، والإلغاء لا يحتاج الكود. الـOTP المحلي ليس عامل تحقق حقيقيًا.

الرسائل محفوظة في جلسة المتصفح فقط؛ تحديث المتصفح الكامل قد يفقد سجل العرض.
من القائمة الجانبية افتح «استكمال طلب سابق»، ثم «اعرض آخر طلباتي»، واختار الطلب
واضغط «استكمل الطلب» لاسترجاع البيانات الناقصة أو حالة التأكيد من قاعدة البيانات.
من «سجل العمليات» راجع الأحداث في تبويب «العمليات والتأكيدات»، والـnative checkpoints
في «مراحل المساعد المحفوظة». اضغط «تحديث السجل» بعد تجربة جديدة.

الخدمة مرتبطة بـ127.0.0.1 فقط. لا تنشرها على الشبكة أو الإنترنت باعتبارها إعداد إنتاج؛
هذا إعداد Demo محلي بنفس سياق المشروع الحالي.

## إدارة التشغيل

```bash
/usr/bin/python3 scripts/local_ui.py status
/usr/bin/python3 scripts/local_ui.py logs
/usr/bin/python3 scripts/local_ui.py stop
```

تشغيل بدون Docker داخل بيئة Python منفصلة:

```bash
pip install -r requirements-ui.txt
streamlit run ui/app.py --server.address=127.0.0.1 --server.port=8501 --browser.gatherUsageStats=false
```

يمكن ضبط `BANKWISE_API_URL` في بيئة السيرفر فقط، ولا يوجد حقل URL يقبل إدخال المستخدم.
طلبات تسجيل الدخول والتأكيد لا تتبع redirects.

## الاختبارات

```bash
python -m pytest tests/ui -q
```

تستخدم `Streamlit AppTest` مع API وهمي، وتشمل عزل الجلسات، انتهاء التوكن،
التحقق من المستفيد، الموافقة الصريحة، عدم تكرار التأكيد عند rerun، وجميع الصفحات.
الاختبارات لا تخصم من الحسابات التجريبية القائمة.
المعاينة البصرية في المتصفح لم تُجرَ لأن أداة المتصفح رفضت فتح الـorigin المحلي.

للاختبار الحي عبر Streamlit AppTest مع الخدمة المحلية والموديل الحقيقي:
```bash
PYTHONPATH=ui python scripts/smoke_streamlit.py
```
يقرأ بيانات الدخول محليًا ولا يطبع كلمات المرور أو ينفّذ عمليات مالية.
