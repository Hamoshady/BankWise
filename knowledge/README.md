# سياسات الخدمات

عدّل ملفات Markdown داخل `policies/` لإضافة قواعد مشروعك المعتمدة. الملفات الحالية
قواعد محاكاة لبنك افتراضي صُممت بتفويض صاحب المشروع، وليست سياسات بنك حقيقي.
راجع POLICY_DECISIONS.md للأرقام والقرارات. لا تضع بيانات عملاء فيها.
كل ملف يحتوي وصف الخدمة ومتطلباتها وما يحتاج اعتمادًا قبل الإطلاق.

الاستيراد عملية محلية للمسؤول فقط، مع توقف الـAPI لضمان كاتب واحد لسجل التدقيق.
من المجلد الأصلي، بعد إعداد Docker والبيئة كما في docs/local_api.md:

```bash
python3 scripts/local_api.py import-policies
```

الأمر ده بيوقف الـAPI، يستورد ملفات `knowledge/policies/*.md`، ويرجّع الـAPI تاني، وينتظر
`/health/ready`. لازم تشغّله **بعد أي تعديل في ملفات السياسات**، لأن الـAPI مش بيعيد
تحميل الملفات لوحده وهيفضل يجاوب من النسخة القديمة.

`--force` لإعادة فهرسة الملفات غير المتغيرة (بعد تغيير الـchunker أو موديل الـembeddings):

```bash
python3 scripts/local_api.py import-policies --force
```

`--prune` لحذف السياسات اللي ملفاتها اتشالت (الحذف مش تلقائي، والمجلد الفاضي بيترفض):

```bash
python3 scripts/local_api.py import-policies --prune
```

يشغّل الاستيراد أول مرة ثم فقط بعد تعديل السياسات؛ الملفات غير المتغيرة لا يعاد
تخزينها. بعد تغيير الـchunker أو موديل الـembeddings استخدم `--force` لإعادة الفهرسة:
`python -m bankwise.rag.import_policies /policies --force`.
لحذف السياسات التي أُزيلت ملفاتها من المجلد استخدم `--prune` (لا يحدث الحذف تلقائيًا،
والاستيراد يرفض مجلدًا فارغًا حتى لا يمسح المكتبة بالخطأ):
`python -m bankwise.rag.import_policies /policies --prune`.
لا توجد واجهة نشر عامة.
السياسات مملوكة لحساب داخلي معطل، ولا يستطيع العميل تعديلها أو حذفها.
دور `customer` يمنح قراءة RAG فقط؛ لمعالجة البطاقة يحتاج الحساب كذلك
`identity_processor`، ولعرض طلب الهوية يحتاج `operator` وفق RBAC الحالي.
طلبات RAG لحساب customer (بدون دور معرفي) تبحث فقط في المكتبة المشتركة، وليس في
مستندات العملاء. حسابات knowledge_user القديمة ما زالت تدير مكتباتها الخاصة
للتوافق، والحساب الذي يحمل الدورين يحتفظ بنطاقه الخاص.

هذه الملفات تشرح الخدمات؛ كشف حساب حقيقي والتحويل والقرض وتحليل المعاملات تحتاج
خدمات مالية مستقلة لم تُنفذ هنا. OCR يقرأ البطاقة ويفحصها؛ لا يثبت ملكية الهوية
بدون مطابقة وجه وفحص حيوية.


## اختبار السياسات العربية

مجموعة القبول `evaluation/rag/policy_acceptance_cases.json` تختبر الأرقام والشروط
والنفي والصياغة العامية والامتناع عن الأسئلة غير المدعومة. الاختبار يفحص النص
الفعلي للإجابة وارتباط كل مقتطف بالمصدر، وليس اسم المصدر فقط.

```bash
docker run --rm --network none \
  -v bankwise-rag-models:/rag-models:ro -v "$PWD:/work:ro" -w /work \
  -e PYTHONPATH=/work/src -e BANKWISE_TEST_SEMANTIC=1 -e HF_HUB_OFFLINE=1 \
  bankwise-ai:semantic python -m pytest \
  tests/integration/test_rag_policy_acceptance.py tests/unit/test_policy_documents.py \
  -q -p no:cacheprovider --tb=short
```

هذه حالات تطوير وقبول محدودة وليست قياسًا مستقلًا لجودة العربية كلها. راجع كذلك
أسئلة جديدة يدويًا قبل العرض النهائي. غيّر شروط البنك الافتراضي فقط بقرار تصميم
واضح، ولا تجعل أرقام المحاكاة تبدو قواعد مصرفية فعلية.
